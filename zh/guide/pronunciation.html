发音与发音包 ​

词悦有两种发音来源：发音包（.mdd 或 .zip / .zips 里的录音）和 TTS（系统语音合成）。

三种发音模式 ​

模式行为
优先音频包，TTS 兜底先找音频包里的录音，找不到就用 TTS 朗读
仅音频包只播录音，没有就直接静音，不会朗读
仅 TTS不使用音频包，一律朗读

音频包可以在 设置 → 发音 → 发音包 里添加，支持多个，拖动可以调整优先级。

打包形式 ​

发音包可以是 .mdd，也可以是普通 zip——扩展名 .zip 或 .zips（后者是 GoldenDict 给发音包的扩展名，文件本身就是普通 zip）。

形式想改里面某个文件时
.mddMDict 私有格式，要用 MdxBuilder 或 mdict-utils 解包再重新打包
.zip / .zips普通 zip，任何压缩软件都能替换，不需要专用工具

需要调整某个发音时，zip 形式省事得多：解出来、换掉、压回去。两种形式可以混用，拖动调整优先级对它们一视同仁。

哪些格式能播 ​

决定能不能出声的不是词悦，而是系统解码器（Android 用的是 MediaPlayer）。

格式情况
MP3最稳，推荐
WAV（PCM）稳；ADPCM、μ-law、A-law 的 WAV 取决于设备
AAC / M4AAndroid 原生支持，ADTS（裸 .aac）与 MP4 容器都可以
OGG Vorbis支持
Ogg Speex（.spx）不支持，Android 没有 Speex 解码器
Opus取决于系统版本与容器，Ogg Opus 在较旧系统上不可靠

.spx 是最容易踩到的一个坑。

WAV 也一样，扩展名说明不了里面是什么：fmt 字段可能是 PCM、ADPCM、μ-law，也可能是内嵌 MP3（fmt=0x55）。最后一种在实测设备上能正常播放——系统会把它交给 MP3 解码器，所以看到 .wav 不必先怀疑格式，先按下一节确认日志里有没有 Playing sound。

点了没声音怎么办 ​

两种情况：

弹出了「该词典的发音音频使用了此设备不支持的格式」 说明资源找到了、也交给了解码器，但系统解不了这个格式。看下一节转换。

完全没反应，也没有提示 说明这个 sound:// 链接没有指向一个存在的资源（MDX 词典是和 .mdd 里的实际路径对不上，StarDict 词典则是和 res/ 目录或资源归档里的路径对不上；或者这本词典根本没有发音资源）。可以用 adb logcat | grep -E "Playing sound|Failed to play audio bytes" 确认点击到底有没有走到播放。

把不支持的发音包换成能播的格式 ​

关键前提：如果不修改 mdx 文件中的内容，那就不要改 mdd 包中的文件名（StarDict 词典则是不要改 res/ 或资源归档里的文件名）。词条正文里写的是 sound://ID1234.spx 这样的引用，改扩展名之后链接就指向了一个不存在的资源，会变成「点了没反应」，比原来更糟。

好在 Ogg Speex 和 Ogg Vorbis 用的是同一个容器，所以可以把 .spx 里的内容换成 Vorbis，文件名保持 .spx：容器一致、扩展名一致、词悦传的 MIME（audio/ogg）也仍然正确，Android 就能正常解码。

1. 解包 ​

图形界面用 MdxExport（Windows），选中 .mdd 导出到一个文件夹；命令行用 mdict-utils：

bash
pip install mdict-utils
mdict-utils mddunpack 词典.mdd     # 分卷则是 词典.1.mdd、词典.2.mdd……逐个解

有些词典把插图和发音放在同一个 .mdd 里，解包后请保留全部文件，只处理音频。

2. 转换（原地替换，文件名不变） ​

bash
# 把 Ogg Speex 换成 Ogg Vorbis，输出仍写回 .spx 文件名
find . -type f -iname '*.spx' -print0 | while IFS= read -r -d '' f; do
  ffmpeg -nostdin -loglevel error -y -i "$f" \
    -c:a libvorbis -q:a 3 -ac 1 -ar 22050 \
    -f ogg "${f%.spx}.tmp" && mv "${f%.spx}.tmp" "$f"
done

参数说明：

  • -f ogg 必须显式指定，否则 ffmpeg 会因为输出扩展名是 .spx 而找不到容器
  • -ac 1 -ar 22050：单词读音单声道 22.05 kHz 足够，体积约为原来的两倍以内
  • -q:a 3：Vorbis 的质量档，3 对语音已经够用

转换完可以抽查一个文件确认：

bash
file 某个文件.spx      # 应显示 "Ogg data, Vorbis audio"

3. 打包 ​

图形界面用 MdxBuilder，类型选 MDD，源目录选解包出来的文件夹，输出同名 .mdd；命令行：

bash
mdict-utils mddpack ./解包目录 词典.mdd

分卷的话按原来的卷号分别打包（.1.mdd、.2.mdd……），卷数不必和原来一致，但同一个卷里的文件顺序最好保持不变。

4. 放回并重新添加 ​

替换掉原来的 .mdd（或放到任意目录），在 设置 → 发音 → 发音包 里移除旧的、添加新的，然后查词试听。

常见坑 ​

  • 改了扩展名，mdx文件却还是不变：.mdx 里的 sound://…spx 不会跟着变，链接直接失效。要么保持扩展名（推荐上面的 Vorbis 方案），要么连 .mdx 一起重打包。
  • 只改了部分文件：同一本词典里可能混着 .spx 和 .mp3，转之前先 find . -type f | sed 's/.*\.//' | sort | uniq -c 看一眼。
  • 路径分隔符：MDD 里的路径可能是 \img\a.spx 也可能是 /img/a.spx，重新打包时保持原样，不要手改。
  • 发音包和正文词典是两回事：词典自带的声音，只要词条里有 sound:// 链接就能直接播，不需要在设置里「添加发音包」——MDX 词典从 .mdd 里取，StarDict 词典从 res/ 或资源归档（res.zip、<name>.res.zip、res/res.zip）里取；「添加发音包」是给「查任意单词都能按键朗读」这个功能用的。
